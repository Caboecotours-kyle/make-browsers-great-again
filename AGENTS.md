# Agent instructions

## Commits

Commit as soon as you finish implementing a feature or fixing a bug, before
handing the turn back to the user. Don't wait to be asked. Make one commit per
feature or fix. Include only the files that change touched, and never commit
unrelated work that was already in the tree.

Follow the existing history's style. The subject line says what changed from
the user's point of view, for example "Give MBGA its own icon, and let it open
web pages from Finder". The body explains why and how.
